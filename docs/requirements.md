# Requirements and their checks

Lens's requirements are the lists in the [README](https://github.com/adeelahmad/lense#what-you-can-do-with-it): what
is built, what is [in progress](https://github.com/adeelahmad/lense#in-progress) (an open pull request) and what is
[planned](https://github.com/adeelahmad/lense#planned). Each built item there links its section here, and each row of
a section names the checks that fail when that requirement stops being true: a test, a
[clicks journey](https://github.com/adeelahmad/lense/blob/main/ci/clicks/README.md) and the number it is held to, or
the CI workflow that builds or tests it. A requirement nothing checks yet says so and links the issue that adds one.

## How the checks are kept

`make requirements` runs
[`ci/check_requirements.py`](https://github.com/adeelahmad/lense/blob/main/ci/check_requirements.py), and pre-commit
runs it on every pull request, so drift shows up in CI. It fails when:

- a built item in the README links no section here, or a section here is linked by no item;
- a check is gone: its file, a test function or class in a Python test, a quoted name (a test's title, a journey's
  id) in a script, a job or step `name:` in a workflow, or a journey in a clicks baseline;
- a measured number is no longer met: `journey` ≤ N clicks (or keys) in
  [`ci/clicks/baseline.json`](https://github.com/adeelahmad/lense/blob/main/ci/clicks/baseline.json) (a computer) or
  [`baseline-phone.json`](https://github.com/adeelahmad/lense/blob/main/ci/clicks/baseline-phone.json) (a phone), or
  the journey fails there;
- a requirement with no check yet links no issue;
- an In progress item links no pull request, or one the changelog already lists as released;
- a Planned item links nowhere.

The script checks that a check exists, not that it passes: CI runs the tests, the Clicks workflow the journeys. A
check named here runs in CI rather than skipping there (a test that needs a program the runners lack is not a check
yet). When a pull request builds something, it adds a line to the README's built list and a row here, and takes its
own line out of In progress. Renaming or removing a test that a row names means changing the row in the same pull
request, to another check that proves the same thing; loosening a requirement or its number waits for the owner
([AGENTS.md](https://github.com/adeelahmad/lense/blob/main/AGENTS.md)).
